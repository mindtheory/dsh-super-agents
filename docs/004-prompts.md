# 004 提示词系统（Prompts）

本文说明系统里每一段"给模型读的文字"归谁写、何时生效、如何演进。承接
[000 理念](000-philosophy.md)：团队用文字描述的行为是提示词，不是设置项。

## 提示词清单（谁、何时、多大）

| 段 | 消费者 | 生成时机 | 内容 |
| --- | --- | --- | --- |
| 任务提示词 | Run 的 worker 会话 | 每次 Run 组装 | 角色人设 → playbook（尾部截断 2400 字符）→ 任务文本 → 产物契约 |
| 蒸馏提示词 | reflection 会话 | 每次蒸馏 | 教训格式约束 + 任务节选 + 产物节选 + 输出契约 |
| 系统提示词段 | 宿主主会话 | 每次模型请求 | 在册 agent 清单（空 = 空段不占 token） |
| super-agents 技能 | 宿主主会话 | 按需加载 | 教宿主模型怎么用 sa_* 工具（创建→派活→回收→调度的标准流程） |

## 从原型采纳的三条装配原则

1. **每行一句、可 diff。** 原型的 prompts/*.md 全部是"一行一条自包含祈使句"，可逐行
   覆盖、逐行 diff。我们的蒸馏提示词与产物契约同样短句化——长散文无法回归测试。
2. **最易变的放最后。** 原型把 Policy 段放提示词末尾，策略变更不动前面的前缀缓存。
   我们的任务提示词把 playbook（每 Run 都可能变）放人设之后、任务文本之前；若将来
   做提示词版本化，Policy 类内容一律追加在尾。
3. **约束下沉到工具层，提示词只兜底。** 原型的第一优先级是"工具强制事实"（reply 长度
   上限、purpose 校验、sleep 守卫），提示词改不动它。我们的对应物：产物路径契约由
   runner 校验（读不到文件就是 `done_no_artifact`，模型嘴上说完成没用）；playbook 合并
   只收 `- ` 行（格式闸门在代码里，不在提示词里恳求）。

## 优先级（外部文本永远是数据）

从强到弱：宿主强制事实（沙箱、工具面）> 产物契约与格式闸门 > 角色人设与 playbook >
任务文本 > 任务里引用的外部内容（网页、仓库文件、他人消息）。外部内容可以成为任务的
**主题**，但任务文本本身只来自操作者（人或调度行）。若任务要求 agent 去读外部内容，
读到的东西不得改变产物契约与输出格式——这条写死在契约文本里。

## 演进：playbook 就是最简提示词版本化

原型的完整机制（不可变版本 + base 快照 + Default updated diff）适合多团队产品。
个人/小团队场景下，playbook 承担了演进职责：每次运行把"下次直接有用"的教训追加进来，
去重、有界、丢最旧。升级插件版本时 playbook 不动（它是数据不是代码）；若新版本的
蒸馏提示词变好，旧教训会随 60 行窗口自然淘汰。
